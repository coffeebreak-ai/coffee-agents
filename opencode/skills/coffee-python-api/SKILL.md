# Coffee: HTTP на Flask

Фреймворк API — `flask-openapi3` с `APIBlueprint`. Pydantic-схемы обязательны, Swagger отдаётся из коробки.

```python
bp = APIBlueprint("orders", __name__, url_prefix="/api/v1")


@bp.post("/orders", tags=["orders"], responses={201: OrderOut})
def create_order(body: OrderIn) -> OrderOut:
    return OrderOut.model_validate(service.create(body))
```

## Схемы

* `schemas/` — только Pydantic-модели. `OrderIn` и `OrderOut` раздельные: вход и выход не переиспользуют одну модель.
* Ручной разбор `request.json` запрещён, валидация только через схему.
* Ошибки валидации возвращает фреймворк в формате 422, свой текст не переопределять.

## Правила эндпоинта

* Один роут — один вызов сервиса. Бизнес-логика в роуте запрещена.
* Коды статусов явные: `200`, `201` на создание, `204` на удаление, `404` на отсутствие.
* `try/except` в роутах не пишется: доменные исключения обрабатываются в `register_error_handlers`.
* Список отдаётся страницей: `limit`, `offset`, в ответе `items` и `total`.
* POST, который может повториться, принимает заголовок `Idempotency-Key`; отсутствие ключа — ошибка, а не тихий повтор.

## Ошибки

`errors.py` содержит иерархию доменных исключений и их маппинг в статусы в одном месте.
Новый тип ошибки добавляется туда, а не в роут.

## Документация

Описание эндпоинта, теги и примеры — в декораторе. Схема открыта на `/docs`; авторизация в схеме описывается через `security`.
