# Coffee: разработка на Python

Python 3.11+, целевой 3.12. Пакеты — `uv`, проверка — `ruff` и `mypy`, тесты — `pytest`.

## Типизация

* Аннотации у всех аргументов, возвращаемых значений и полей классов. Вместо `Optional[X]` — `X | None`.
* Параметры принимай через `collections.abc` (`Sequence`, `Mapping`, `Iterable`), если мутация не нужна.
* Контракт без наследования — `Protocol`; структурированный словарь — `TypedDict`; константа — `Final`; набор состояний — `Literal`.
* `Any` запрещён там, где структура описывается через `TypedDict`, `dataclass` или `BaseModel`. Исчерпывающие ветки закрывай `assert_never`.
* `mypy` в режиме `strict` не ослабляй. `# type: ignore[код]` — только с кодом ошибки; неиспользуемые ignore ловит `warn_unused_ignores`.
* Настройки — `pydantic-settings`, не `os.environ` по коду.

## Стандартная библиотека

* `functools.cache` и `cached_property` — для чистых вычислений; I/O и состояние не кешируй.
* Потоковая обработка — `itertools`, а не промежуточные списки.
* Очереди и счётчики — `collections.deque`, `defaultdict`, `Counter`.
* Ресурсы — `contextlib.suppress` для ожидаемого отсутствия и `ExitStack` для динамического набора.
* Значимые объекты — `dataclass`; неизменяемые — `frozen=True`, `slots=True`; коллекции — `field(default_factory=...)`.

## Pydantic v2

* Все границы валидируются моделью: тело запроса, ответ внешнего API, сообщение очереди, конфиг.
* Только API v2: `model_validate`, `model_dump`, `model_dump_json`, `field_validator`. Методы `parse_obj`, `.dict()`, `.json()` устарели.
* Наружу отдаётся `model_dump(mode="json")`; `Decimal` и даты сериализуются строкой.

## Синхронность

* **Асинхронной обработки нет.** Запрещены `async def`, `await`, `asyncio` и async-драйверы: проект синхронный.
* Простой параллелизм — только при крайней необходимости. Предпочтительно выносить работу во внешний многопоточный оркестратор: он управляет несколькими Python-воркерами извне и распределяет нагрузку по всем ядрам.
* Внутри процесса параллельные внешние вызовы — `concurrent.futures.ThreadPoolExecutor` с явным лимитом воркеров и таймаутом. Только для I/O, не для CPU: GIL.
* Соединения и пулы создаются один раз в фабрике приложения, а не на каждый запрос.

## Ошибки и логи

* Ловить конкретные исключения. `except:` и `except Exception: pass` запрещены.
* Ошибка логируется с `logger.exception(...)` и структурным контекстом: ID сущности, ключ идемпотентности, внешний сервис.
* Логи — `logging`, не `print`; настройка один раз в точке входа, поля структурные.
* Деньги и точные расчёты — `decimal.Decimal`, не `float`.

## Внешние вызовы

* HTTP — синхронный `httpx.Client`, не `requests`. Таймаут задаётся всегда и явно.
* Повторы — `tenacity` с лимитом попыток, задержкой и jitter. Повторяются только идемпотентные операции.
* Каждый вызов — таймаут, метрика и лог; проглоченный ответ внешнего сервиса запрещён.

## Стиль

* Секреты, URL и таймауты — только из настроек.
* Изменяемые значения по умолчанию запрещены (`def f(x=[])`); пути — `pathlib.Path`.
* Комментарии и docstring — только по прямой просьбе.

## Тесты

* `pytest`: фикстуры с `yield` и очисткой, временные файлы — `tmp_path`, наборы — `parametrize`.
* Ожидаемое исключение — `pytest.raises(..., match=...)`; мок — на границе (HTTP, БД, очередь), не на внутренних функциях.
* Тесты проекта правь вместе с кодом; временные проверки гипотез в diff не оставляй.

## Проверка

* Конфиги линтеров правь только по просьбе — любую правку информируй: добавил или изменил поле, иногда достаточно просто добавил комментарий.
