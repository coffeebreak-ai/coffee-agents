# Coffee: Go

Локальный `AGENTS.md` и уже принятые каталоги важнее. Чужой репозиторий как образец не открывай.

Формулу пиши на месте. Микрометод — только ресивер типа. Helper — если есть ветвление, I/O, лок или несколько шагов. Файл сверху вниз: типы, конструктор, основная логика, приватное внизу. Один вход с `ctx`, без пары `Foo`/`FooCtx`.

Комментарии, GoDoc и TODO — только по прямой просьбе. Исключение одно: swag-аннотации, их требует `coffee-gin-swagger`. `//nolint` запрещён всегда: его ловит `nolintlint`. Замечание исправляй в коде. Лог — не комментарий: русский текст, поля как в коде.

Ошибку не глуши. Оборачивай `fmt.Errorf("действие: %w", err)`. `panic` только на старте. `ctx` — первый аргумент I/O, в поле структуры не клади. Ресурсы закрывай через `defer`. Горутина останавливается по `ctx.Done()` и ждётся через `WaitGroup` или `errgroup`.

Данные: внутренний слайс или мапу не отдавай напрямую — `slices.Clone`/`maps.Clone`; принятый слайс копируй, если хранишь его в структуре. Размер известен — `make([]T, 0, n)`. I/O, БД и тяжёлый счёт не держи под `mu.Lock()`.

`http.DefaultClient`, `http.Get`, `http.Post` не используй: только явный `&http.Client{Timeout: ...}`. Для чтения хватает `defer f.Close()`, для записи ошибку `Close` и `Commit` проверяй явно, `Rollback` — `defer` сразу после `BeginTx`. Ожидаемое бизнес-состояние — sentinel-ошибка и `errors.Is`, не сравнение `err.Error()`.

`go.mod` не меняй без прямой просьбы. Деньги и объёмы — не `float64`.

## Линтер

Конфиг не читай: он лежит в `.golangci.yml` и меняется без тебя. Замечания линтера правь в коде. Конфиг правь только по прямой просьбе: вместо запрета любую правку информируй — добавил или изменил поле, иногда проще просто добавил комментарий. Ошибка `unsupported version of the configuration` значит, что версии бинаря и конфига разошлись: доложи её и не мигрируй конфиг.

Слои, репозиторий и Makefile — `coffee-go-layout`. HTTP и swag — `coffee-gin-swagger`. Таймауты, повторы, метрики — `coffee-go-calls`. Грузи их только если задача про это.
